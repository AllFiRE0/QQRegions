# QQRegions — редактор меню (формат как у DeluxeMenus)

Все меню лежат в `plugins/QQRegions/menus/*.yml`. Один файл = одно или
несколько меню (секция `Menus`). Любой `.yml` из этой папки подхватывается
без пересборки плагина. Изменения применяются через `/region reload`.

По команде `/region` (а также `/tr`, `/territory` и другие алиасы) открывается
главное меню — его файл `main.yml`. Меню можно открывать кнопками, командами
`open-commands` или псевдокомандой `@menu:<имя файла>`.

---

## 1. Минимальный пример

```yaml
config-version: 1
update_interval: 20              # общий интервал обновления (тики)

Menus:
  myshop:
    priority: 5                  # выше = приоритетнее при нескольких шаблонах
    title: "&6Мой магазин"
    size: 6                      # строки 1-6
    fill:
      enabled: true
      material: BLACK_STAINED_GLASS_PANE
      name: " "
    buttons:
      home:
        slot: 4
        material: PLAYER_HEAD
        name: "&eГлавное меню"
        lore:
          - "&7Открывает меню main.yml"
        commands:
          - "@menu:main"
      info:
        slot: 10
        material: BOOK
        name: "&eИнфо"
        commands:
          - "spawn"              # обычные команды идут от имени игрока
    open-commands:               # по /myshop меню откроется сразу
      - myshop
```

## 2. Кнопки (buttons)

Ключ кнопки (например `home`) — просто имя, ид в меню. Поля:

| Поле | Описание |
|---|---|
| `slot` | Номер слота 0..(size*9-1). Если нет — слот выдаётся по порядку. |
| `material` | Материал кнопки, например `DIAMOND`, `PLAYER_HEAD`. |
| `amount` | Количество предмета (по умолчанию 1). |
| `name` | Название (цвета `&`, переменные `{...}`). |
| `lore` | Описание — список строк с переменными. |
| `commands` | Список команд кнопки (см. раздел 3). Выполняются по очереди. |
| `permission` | Право, без которого кнопка не кликается (клик молча игнорируется). |
| `tooltip` | `false` — скрыть всплывающее окно при наведении **только у этой кнопки** (как кнопки, так и у `fill`, по умолчанию `true`). |
| `role-required` | Показ по роли в регионе: `owner`, `member`, `other`, `""` = все. |

Перенос кнопки из одного меню в другое = копирование блока `ключ:` из
`buttons` одного файла в другой (и правка `@menu:` если нужно).

## 3. Команды кнопки

### 3.1. Псевдокоманды движка
| Команда | Что делает |
|---|---|
| `@menu:<имя файла>` | Открыть другое меню (например `@menu:blocks`) |
| `@page:prev` / `@page:next` | Страница назад/вперёд (используется в navigation) |
| `@back` | Вернуться в предыдущее меню (история до 20 шагов) |
| `close` | Закрыть меню |

### 3.2. Псевдокоманды плагина
| Команда | Что делает |
|---|---|
| `@region-info` | Info-меню региона, где стоит игрок (по роли) |
| `@region-info-or-pick` | «Моя территория»: в регионе — info, иначе — меню выбора территории |
| `@region-delete` | Подтверждённое удаление региона (проверка роли владельца/админа + права `qqregions.delete`) |
| `@region-search` | Запросить ввод названия в чат → меню результатов |
| `@player-search` | Поиск игрока по нику в меню «Поиск игроков»: ввод нику в чат → фильтр списка по regex |
| `@select` | Включить интерактивный выбор (создание территории, как `/region select`) |
| `@rinfo:<мир>:<регион>` | Открыть info конкретного региона |
| `@flag-search` | Поиск флагов по названию в меню флагов |
| `@market-search` | Фильтр предложений рынка по названию |
| `@market-tab` | Переключить вкладку рынка «Мои/Все объявления» |
| `@market-mine` | Открыть рынок сразу во вкладке «Мои объявления» |
| `@mkt-cancel:<id>` | Отмена объявления (меню подтверждения marketconfirm.yml) |
| `@sort` | Цикл сортировки рынка: название/цена/дефолт |
| `@ps-sort` | Цикл сортировки поиска игроков: A-Z/Z-A/баланс/регионы±/дистанция± |
| `@rpsort` | Цикл сортировки выбора территории: близкие/дальние/A-Z/Z-A/люди±/площадь± |
| `@teleport` | Телепорт в безопасную точку региона (владелец/админ): на твёрдом блоке, не в лаве/воде и не в пустоте |
| `@highlight` | Подсветка границ текущего региона |
| `@flag:<флаг>:allow|deny|default` | Поставить флаг региона (`default` — снять, как `/rg flag -r`) |
| `@add:owner` / `@add:member` | Ввод ника в чат → меню подтверждения → добавить владельца/участника |
| `@player-del:<ник>` | Убрать игрока из региона (открывает меню подтверждения playerconfirm.yml) |
| `@pc-add` | Кнопка «Добавить» в playerconfirm.yml: ЛКМ/ПКМ — участник, Shift+ЛКМ/Shift+ПКМ — владелец |
| `@pc-remove` | Кнопка «Удалить» в playerconfirm.yml: убрать игрока из территории |
| `@pc-confirm` | Legacy: выполнить операцию из контекста playerconfirm.yml (добавить/убрать игрока) |
| `@market:buy:<id>` | Купить предложение рынка |
| `@market:rent:<id>` | Арендовать |
| `@market:autorent:<id>` | Переключить автовозврат аренды (своё объявление) |
| `@market:tp:<id>` | Телепорт к региону объявления («посмотреть в живую») |
| `@shop-buy:<id>` | Купить товар магазина (флаги, блоки, «+регион») |
| `@raid:<действие>` | Действия рейда клана |

Кнопки объявлений рынка (`menus/market.yml`, `@market:*`) обрабатываются
по ТИПУ КЛИКА (не по слотам): ЛКМ — купить/арендовать (своё во «Все» —
телепорт); ПКМ — отмена (вкладка «Мои объявления»); Шифт+ЛКМ — срок
объявления; Шифт+ПКМ — срок аренды. Сроки — через чат-ввод, лимиты
(1 час..1 год) настраиваются в config.yml market.rent.

### 3.3. Обычные команды
- Любая команда без спец-префикса выполняется **от имени игрока**:
  `commands: [ "spawn" ]`, `commands: [ "msg admin Всем привет" ]`.
- `asConsole! <команда>` — **от консоли**: `commands: [ "asConsole! eco give %player_name% 500" ]`.
- `asPlayer! <команда>` — явно от игрока: `commands: [ "asPlayer! sethome" ]`.

Можно несколько команд подряд:
```yaml
commands:
  - "asConsole! eco give %player_name% 500"
  - "@menu:main"
```

## 4. Переменные и PlaceholderAPI

В `name`/`lore` и в кнопках работают:

- `{переменные}` контекста меню:
  `{player}`, `{world}`, `{region}`, `{region-name}`, `{owners}`, `{members}`,
  `{role}`, `{page}`, `{pages}`, `{back-target}`, а в info/флагах: `{type}`,
  `{area}`, `{volume}`, `{priority}`, `{status}`, `{flag-name}`, `{group}` ...
  В info доступны и лимиты игрока: `{my-regions}` `{max-regions}`
  `{max-blocks}` (∞ — если лимита нет/право админа).
- `%PlaceholderAPI%` — если PlaceholderAPI подключён (например `%player_name%`).
- В `material` тоже работают `{переменные}`. Специальный синтаксис
  `PLAYER_HEAD:{uuid}` (или `PLAYER_HEAD:{pc-uuid}` с переменной) ставит
  голову с игровым скином владельца UUID — удобно для кнопок-портретов.

## 5. Страницы внутри меню

Список `menu-slots` задаёт слоты «динамических» кнопок. Сколько в списке
слотов — столько кнопок на одной странице. Если динамических элементов
больше — появляется пагинация (navigation, по умолчанию слоты 45/53).

```yaml
    navigation:
      prev:
        material: ARROW
        name: "&eНазад"
        slot: 47            # не обязательно — по умолчанию 45
      next:
        material: ARROW
        name: "&eВперёд"
        slot: 51            # по умолчанию 53
    menu-slots:
      - 10
      - 11
      - 19
      - 20
```

Что попадает в эти слоты — определяет тип меню:
- `main`, `market` — предложения рынка (продажа/аренда);
- `regionsearch` — результаты поиска регионов;
- `players` — владельцы/участники региона;
- `playerconfirm` — подтверждение добавления/удаления игрока (статичные кнопки);
- `flags`, `myflags`, `flagshop` — флаги (dynamic-flags / purchased-flags);
- `blocks` — пакеты площади и «+регионов».

Своё меню с простыми статичными кнопками пагинации не требует — просто
не пишите `menu-slots` и `navigation`.

## 6. Динамические списки (как у DeluxeMenus)

Секция `dynamic-flags` в меню флагов: флаги из листа регистрированных,
карточка кнопки (material/name/lore), `slots` — пул слотов, `flag-permission-prefix`.
Значения из `states` циклируются по ЛКМ через `{next-state}`; токен `default`
в списке означает «снять флаг» (как `/rg flag -r`, работает дефолт WG) —
по умолчанию `allow` → `deny` → `default`.
Секция `purchased-flags` — для «Моих флагов» (только купленные в магазине).
Секция `dynamic-players` — список участников региона: головы скинов
(`config.yml player-search.head-material` / `head-texture`), имя — цвет ника по
роли (владелец `&#ccbf8f` / участник `&#7db389`), описание единое с «Поиском
игроков» (lang `menu.ps-line-*`): группа, клан, баланс, территории, подсказка
удаления (видна только владельцу территории). Найденный через кнопку
`@player-search` игрок в **playersearch.yml** показывается в списке строк; клик —
меню управления **playerconfirm.yml** (кнопка «Добавить игрока» `@pc-add` —
ЛКМ участник / Shift+ЛКМ владелец, кнопка «Удалить» `@pc-remove`, инфо-кнопка
об игроке; `@back` — отмена); материал `PLAYER_HEAD:{pc-uuid}` подставляет
голову скин игрока.

Кнопка-фильтр `@rpsort` / `@ps-sort` — цикл сортировки списка. В контекст
меню подставляется `{rp-sort-list}` / `{ps-sort-list}` — цветной список всех
режимов, текущий подсвечен `&a`, остальные `&7` (по одному на строку).
Используйте его в лоре кнопки («&eСортировка»), чтобы не выводить режим в
название. Названия режимов — lang `menu.rp-sort-*` / `menu.ps-sort-*`
(ключ = id режима), сообщение смены — `actionbar:3!...` в lang.

## 7. Шаблоны одного файла (приоритет и роли)

Под одним ключом `Menus.<имя>` можно описать НЕСКОЛЬКО шаблонов с ключом
`role-required` (обычно `flags.yml`, `info.yml`, `players.yml` так и сделаны).
Для игрока выбирается шаблон с наибольшим `priority`, которому он отвечает:
совпадает `role-required`, есть `permission-group`, выполняется
`placeholder-group` (PAPI), по умолчанию `""` — подходит всем.

Пример — разные кнопки для владельца и чужака в одном меню:
```yaml
  default:
    priority: 5
    role-required: ""       # базовый шаблон — для всех
    ...кнопки...
  owner:
    priority: 6
    role-required: owner    # для владельцев — кнопки управления
    ...кнопки с @add:, @player-del:...
```

## 8. Обновление меню на лету

`update_interval` (тики, 20 = 1 сек) — как часто перерисовывается открытое
меню (lore с ценами/статусами меняется из `%placeholder%` и контекста).
`0` = выключить автообновление этого меню (действия по кнопкам всё равно
перерисовывают). Глобальный дефолт — `menu-update.ticks` в config.yml;
значение в файле меню сильнее.

Анти-автокликер (`menu-update.debounce-after-click`) — ОПЦИОНАЛЕН, по
умолчанию выключен: клики по кнопкам перерисовывают меню СРАЗУ (визуальный
отклик мгновенный). Только если на сервере реальные автокликеры грузят
TPS, включите `debounce-after-click: true`: клик по любой кнопке молча
откладывает следующую перерисовку открытого меню на `update_interval`
тиков — автокликер не может грузить сервер пересборкой инвентаря чаще
раза в interval на игрока. Действие кнопки выполняется мгновенно;
навигация (страницы/другое меню) тоже мгновенная.

После изменения файлов: `/region reload`. Старые файлы из jar обновляются
автоматически при смене `config-version` (бэкап `<имя>.old`), поэтому не
правите встроенные меню прямо на сервере — лучше скопируйте в свой файл.

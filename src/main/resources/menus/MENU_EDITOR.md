# QQRegions — редактор меню (формат как у DeluxeMenus)

Все меню лежат в `plugins/QQRegions/menus/*.yml`. Один файл = одно или
несколько меню (секция `Menus`). Любой `.yml` из этой папки подхватывается
без пересборки плагина. Изменения применяются через `/region reload`.

По команде `/region` (а также `/tr`, `/territory` и другие алиасы) открывается
главное меню — его файл `main.yml`. Меню можно открывать кнопками, командами
`open-commands` или псевдокомандой `@menu:<имя файла>`.

---

## 1. Минимальный пример

```yaml
config-version: 1
update_interval: 20              # общий интервал обновления (тики)

Menus:
  myshop:
    priority: 5                  # выше = приоритетнее при нескольких шаблонах
    title: "&6Мой магазин"
    size: 6                      # строки 1-6
    fill:
      enabled: true
      material: BLACK_STAINED_GLASS_PANE
      name: " "
    buttons:
      home:
        slot: 4
        material: PLAYER_HEAD
        name: "&eГлавное меню"
        lore:
          - "&7Открывает меню main.yml"
        commands:
          - "@menu:main"
      info:
        slot: 10
        material: BOOK
        name: "&eИнфо"
        commands:
          - "spawn"              # обычные команды идут от имени игрока
    open-commands:               # по /myshop меню откроется сразу
      - myshop
```

## 2. Кнопки (buttons)

Ключ кнопки (например `home`) — просто имя, ид в меню. Поля:

| Поле | Описание |
|---|---|
| `slot` | Номер слота 0..(size*9-1). Если нет — слот выдаётся по порядку. |
| `material` | Материал кнопки, например `DIAMOND`, `PLAYER_HEAD`. |
| `amount` | Количество предмета (по умолчанию 1). |
| `name` | Название (цвета `&`, переменные `{...}`). |
| `lore` | Описание — список строк с переменными. |
| `commands` | Список команд кнопки (см. раздел 3). Выполняются по очереди. |
| `permission` | Право, без которого кнопка не кликается (клик молча игнорируется). |
| `role-required` | Показ по роли в регионе: `owner`, `member`, `other`, `""` = все. |

Перенос кнопки из одного меню в другое = копирование блока `ключ:` из
`buttons` одного файла в другой (и правка `@menu:` если нужно).

## 3. Команды кнопки

### 3.1. Псевдокоманды движка
| Команда | Что делает |
|---|---|
| `@menu:<имя файла>` | Открыть другое меню (например `@menu:blocks`) |
| `@page:prev` / `@page:next` | Страница назад/вперёд (используется в navigation) |
| `@back` | Вернуться в предыдущее меню (история до 20 шагов) |
| `close` | Закрыть меню |

### 3.2. Псевдокоманды плагина
| Команда | Что делает |
|---|---|
| `@region-info` | Info-меню региона, где стоит игрок (по роли) |
| `@region-search` | Запросить ввод названия в чат → меню результатов |
| `@rinfo:<мир>:<регион>` | Открыть info конкретного региона |
| `@flag-search` | Поиск флагов по названию в меню флагов |
| `@market-search` | Фильтр предложений рынка по названию |
| `@sort` | Цикл сортировки рынка: название/цена/дефолт |
| `@teleport` | Телепорт в центр региона (владелец/админ) |
| `@highlight` | Подсветка границ текущего региона |
| `@flag:<флаг>:allow|deny` | Поставить флаг региона |
| `@add:owner` / `@add:member` | Ввод ника в чат → добавить владельца/участника |
| `@player-del:<ник>` | Убрать игрока из региона |
| `@market:buy:<id>` | Купить предложение рынка |
| `@market:rent:<id>` | Арендовать |
| `@market:cancel:<id>` | Снять своё объявление |
| `@market:autorent:<id>` | Переключить автовозврат аренды |
| `@market:dur:<id>` | Время размещения аренды |
| `@shop-buy:<id>` | Купить товар магазина (флаги, блоки, «+регион») |
| `@raid:<действие>` | Действия рейда клана |

### 3.3. Обычные команды
- Любая команда без спец-префикса выполняется **от имени игрока**:
  `commands: [ "spawn" ]`, `commands: [ "msg admin Всем привет" ]`.
- `asConsole! <команда>` — **от консоли**: `commands: [ "asConsole! eco give %player_name% 500" ]`.
- `asPlayer! <команда>` — явно от игрока: `commands: [ "asPlayer! sethome" ]`.

Можно несколько команд подряд:
```yaml
commands:
  - "asConsole! eco give %player_name% 500"
  - "@menu:main"
```

## 4. Переменные и PlaceholderAPI

В `name`/`lore` и в кнопках работают:

- `{переменные}` контекста меню:
  `{player}`, `{world}`, `{region}`, `{region-name}`, `{owners}`, `{members}`,
  `{role}`, `{page}`, `{pages}`, `{back-target}`, а в info/флагах: `{type}`,
  `{area}`, `{volume}`, `{priority}`, `{status}`, `{flag-name}`, `{group}` ...
- `%PlaceholderAPI%` — если PlaceholderAPI подключён (например `%player_name%`).

## 5. Страницы внутри меню

Список `menu-slots` задаёт слоты «динамических» кнопок. Сколько в списке
слотов — столько кнопок на одной странице. Если динамических элементов
больше — появляется пагинация (navigation, по умолчанию слоты 45/53).

```yaml
    navigation:
      prev:
        material: ARROW
        name: "&eНазад"
        slot: 47            # не обязательно — по умолчанию 45
      next:
        material: ARROW
        name: "&eВперёд"
        slot: 51            # по умолчанию 53
    menu-slots:
      - 10
      - 11
      - 19
      - 20
```

Что попадает в эти слоты — определяет тип меню:
- `main`, `market` — предложения рынка (продажа/аренда);
- `regionsearch` — результаты поиска регионов;
- `players` — владельцы/участники региона;
- `flags`, `myflags`, `flagshop` — флаги (dynamic-flags / purchased-flags);
- `blocks` — пакеты площади и «+регионов».

Своё меню с простыми статичными кнопками пагинации не требует — просто
не пишите `menu-slots` и `navigation`.

---

## 6. Динамические списки (как у DeluxeMenus)

Секция `dynamic-flags` в меню флагов: флаги из листа регистрированных,
карточка кнопки (material/name/lore), `slots` — пул слотов, `flag-permission-prefix`.
Секция `purchased-flags` — для «Моих флагов» (только купленные в магазине).
Секция `dynamic-players` — список участников региона с `@player-del:<ник>`.

## 7. Шаблоны одного файла (приоритет и роли)

Под одним ключом `Menus.<имя>` можно описать НЕСКОЛЬКО шаблонов с ключом
`role-required` (обычно `flags.yml`, `info.yml`, `players.yml` так и сделаны).
Для игрока выбирается шаблон с наибольшим `priority`, которому он отвечает:
совпадает `role-required`, есть `permission-group`, выполняется
`placeholder-group` (PAPI), по умолчанию `""` — подходит всем.

Пример — разные кнопки для владельца и чужака в одном меню:
```yaml
  default:
    priority: 5
    role-required: ""       # базовый шаблон — для всех
    ...кнопки...
  owner:
    priority: 6
    role-required: owner    # для владельцев — кнопки управления
    ...кнопки с @add:, @player-del:...
```

---

## 8. Обновление меню на лету

`update_interval` (тики, 20 = 1 сек) — как часто перерисовывается открытое
меню (lore с ценами/статусами меняется из `%placeholder%` и контекста).

После изменения файлов: `/region reload`. Старые файлы из jar обновляются
автоматически при смене `config-version` (бэкап `<имя>.old`), поэтому не
правите встроенные меню прямо на сервере — лучше скопируйте в свой файл.
